## 已定位问题：先用 USB 连过之后，改走无线连不上

| 项 | 内容 |
| --- | --- |
| 现象 | 先用 USB 连上 CarPlay，之后拔线改走无线，界面一直停在「正在打开 CarPlay」；取消、重选设备、重进连接页都一样 |
| 定位结论 | 失败在 **iPhone 侧**，不在 DiPlay。这台车在 iPhone 上的 CarPlay 记录是**有线建立**的，iOS 因此把它当有线设备，握手第 6 步回 `0x4E0D WirelessCarPlayUpdate available=false`，之后不再发 `0x4E0E` / `0x4300`，从不加入车机热点 |
| 已排除 | 蓝牙 RFCOMM、iAP2 identification、MFi 认证（0xAA02/0xAA03/0xAA05）、Wi-Fi 配置下发（0x5702 → 0x5703）全部正常 |
| DiPlay 侧修复 | `dev` 提交 `7e9e21c1`：60 秒内给出具体原因文案（两种 cause：`WIRELESS_CARPLAY_UNAVAILABLE` / `WIRELESS_TRANSPORT_NOT_STARTED`）；此类原因不再自动重试（原为每 30 秒重试同一拒绝）；离开连接页真正取消底层尝试，不再被下次尝试 `adoptBackgroundSession` 接管 |
| 车主侧处理 | iPhone 确认 Wi-Fi 已开 → 设置 → 通用 → CarPlay 车载 删除本车 → 重新配对 → **第一次走无线**；此后 USB 与无线均可用 |
| 边界 | 属 iPhone/iOS 行为，DiPlay 只能快速、明确地失败并给出指引，**无法自动绕过**；定位证据来自小米 8（Android 15 / LineageOS）+ 两台 iPhone 的对照日志，领克 01 实车复现待确认 |

完整诊断与握手逐行对照见 `docs/FEATURES.zh-CN.md` 第 [2.5](FEATURES.zh-CN.md#25-连接失败原因怎么看) 节。
